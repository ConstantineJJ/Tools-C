## Ограничения и handoff

Семантическая authority/visual/manual acceptance требуют существующего человеческого
или доменного review; generic attestation importer не реализован. Анализ ограничен
declared graph. Только два обязательных несовместимых предиката дают mandatory
formal conflict FAIL; optional conflicts остаются видимыми без повышения severity.
Truncation не закрывает acceptance и запрещает apply.

Write guard рассчитан на cooperating writers с подтверждённым exclusive ownership:
lock + old-hash rechecks + fsync + atomic replace не являются OS compare-and-swap.
При неизвестной конкуренции — read-only/manual handoff. Process crash может оставить
lock; он не удаляется автоматически. Any new analysis after todo append требует
явного source SHA rebind, повтор уже внесённого state — лишь безопасный NO-OP.

Новый writer и demo не изменяют реальные project tasks автоматически. Настоящие
plan/todo/Pulse обновляются только как авторизованная документация B4/B5.
Сверка с intake baseline: **421/421 outside-scope paths** byte-identical либо
остаются отсутствующими как прежде; все 76 historical deletions сохранены.
HEAD не изменился, staging пуст; чужие QA/character/vehicle правки не захвачены.
Blender-MCP-Co, services и production assets не редактировались этим этапом.
