# DESCRIPTION MODE — разведывательный мех

Учебный прогон из примера пользователя: «Лёгкий разведывательный двуногий мех,
сферический корпус, две энергетические пушки, длинные ноги». Production Blender
сцена не изменялась.

## PASS0.1: constraints

| ID | Требование | Проверка выбранного hero |
|---|---|---|
| R.scout | Лёгкий разведывательный мех | Тонкие звенья и компактный корпус соответствуют visual intent; функциональность не доказана |
| R.biped | Две ноги | Видны две полные ноги |
| R.sphere | Сферический корпус | Основной корпус имеет сферический силуэт |
| R.guns | Две пушки | Видны два боковых оружейных корпуса |
| R.energy | Энергетические пушки | Принят визуальный язык со световыми вставками; скрытый источник энергии не восстановлен |
| R.longlegs | Длинные ноги | Длина ног существенно больше диаметра корпуса |

Исходный текст: [brief](brief.txt). REQUIRED остаётся требованием пользователя,
а не доказательством технической работоспособности.

## PASS0.2–0.3: concept and lock

Один кандидат в режиме SINGLE для ограниченного smoke-прогона. Built-in imagegen,
[точный prompt](concept_prompt.txt), [canonical hero](canonical-hero.png).
Все шесть требований просмотрены и получили PASS. Качество: brief fit 5/5,
silhouette 4/5, plausibility 3/5, reconstruction 4/5, low noise 4/5; всего 20/25.
Автономный выбор сделал агент. Сравнение трёх настоящих изображений здесь не выполнялось.

Identity Lock v1: [manifest](identity-lock.json). Зафиксированы шесть групп:
torso 1, guns 2, legs 2, feet 2, optical elements 2, antenna 1. Приняты серый/бирюзовый
дизайн, панельная оболочка, длинные тонкие звенья и клиновидные стопы. Они CANONICAL,
поскольку это принятые решения выбранного концепта. Не заданные пользователем
цвета и сенсоры не превратились в REQUIRED.

Относительные диапазоны нормированы к H; перспектива неизвестна. Реальные размеры,
шарнирные оси/ход/силовая схема, задняя система охлаждения и внутренности пушек
не определены. Эти зоны SPECULATIVE и отложены. Физическая устойчивость не доказана.

## PASS0.4–0.5: reconstruction and QA

Из frozen hero создан один [четырёхвидовой лист](auxiliary-multiview.png):
front/right/rear/3/4. [Prompt](multiview_prompt.txt) передаёт тот же hash и lock v1.
Hero и manifest после генерации сохранили прежние байты/hashes.

| Criterion | Result | Наблюдение |
|---|---|---|
| identity | PASS | Сферический scout, две боковые пушки, длинные тонкие ноги сохранены |
| proportions | WARN | Боковая поза/сгиб колена не является метрически идентичной фронту |
| part_counts | WARN | Две ноги/пушки читаются, но крайние пушки обрезаны границами листа |
| construction | WARN | Задний круглый люк, панельные швы и закрытые части суставов придуманы; маркировки uncertainty нет |
| handedness | PASS | Антенна меняет экранную сторону между front/rear ожидаемым образом; это не доказывает оси суставов |
| silhouette | PASS | Сфера, длинные ноги и короткие боковые оружейные массы читаются согласованно |

Лист RESTRICTED: подходит для coarse envelope; нельзя брать с него длину обрезанных
пушек, скрытые оси/механизмы или новые canonical-решения. Новая задняя панель
записана как отдельная SPECULATIVE гипотеза, не добавлена в Identity Lock.

Единый выход: [pass0.json](pass0.json). Gate READY_WITH_LIMITS, только MACRO_BLOCKOUT.
Это PASS подготовки/прозрачности ограничений, а не PASS финальной модели или CAD.
