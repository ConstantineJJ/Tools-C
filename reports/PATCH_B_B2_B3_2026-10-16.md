## Результат

Добавлены только три runtime/support файла:
- `tools/project_review.py`: bounded read-only `validate` и узкий `converge`.
- `tests/test_project_review.py`: реальные временные files и subprocess CLI.
- `docs/project-review.md`: точный schema/CLI/status/limit contract.

Реальные интерфейсы:

```powershell
python tools/project_review.py validate review.json --project PROJECT
python tools/project_review.py converge review.json --project PROJECT
python -m unittest discover -s tests -p test_project_review.py -v
```

Packet path project-relative. `schema_version:1` независим от existing contracts
v1: sources/requirements/task refs/artifacts/checks, source hashes и строки,
scoped IDs, requirement revision и L1–L4. Legacy project не обязан иметь packet.
Canonical source root — только через config pointer к установленному Tools_C;
arbitrary extra roots не разрешаются. Source summary/line binding не доказывает
семантическое соответствие или истинность текста.

`file_exists` наблюдает regular file, `sha256` сравнивает фактические bytes,
`manual` сохраняет UNKNOWN. Закрытые checkbox не принимаются за evidence.
Неполные связи, inaccessible evidence и higher-level acceptance остаются OPEN.
Всегда `visual_status: NOT_EVALUATED`; artifact existence не даёт L4 PASS.

`analysis_status` отделён от `acceptance_status`. Exit 0 означает построенный
отчёт, в том числе с acceptance FAIL/OPEN; 1 — invalid/stale input, 2 — usage.
Такое поведение проверено фактическим CLI subprocess, не только библиотекой.
Missing обязательного файла подтверждается наблюдаемым отсутствием; ошибку
доступа не объявляем missing. Existing directory вместо файла — contradicts.
Fingerprint mismatch существующего файла — partial по указанному predicate.
Это узкие structural outcomes, не general semantic convergence B4/B5.

## Сквозная демонстрация

CORE-001 в hash-bound spec.md → B2 в existing todo.md → result artifact → C1
predicate → requirement/acceptance outcome. Выполнены реальные CLI-вызовы на
собственной isolated fixture, не production files:

| Условие | analysis | acceptance | Обоснование |
|---|---|---|---|
| result существует | PASS | PASS | Полная L1 связь и проверенный file predicate |
| result удалён из fixture | PASS | FAIL | missing finding с requirement/check/source line |
| Нужна ручная L4 проверка | PASS | OPEN | manual UNKNOWN; visual NOT_EVALUATED |

Все три subprocess завершились exit 0: это демонстрирует необходимость читать
acceptance fields. Изменение revision не меняет identity того же missing finding.
Source hash/revision включены в report; helper не изменяет todo/исходники.
Демонстрация воспроизводится тестами из чистого checkout через temporary files.
Локальные JSON outcomes сохранены рядом с baseline; raw source text не выводится.
